最近上班已经有整整快三个月，也差点把我自己的博客快忘了。感觉自己的脑子的想法一直很散不是很会组织成一篇有秩序感的文章，也一直懒得更新我的博客，自个文笔和其他我见过的博客相比也是相形见绌。


首先，最近把我的博客重构了一下。看起来不像个毛坯房了，随着这个博客仓库的提交来到 200+我就知道有数不尽的各种样式被尝试过在我的博客上。这次的模仿对象是 OpenAI 的官网，让 Step-5-Preview 在我的 Deepseek Harness 里弄的，意外的是他在 DSH 里没抓到我要的 OpenAI 网页还是能给我复现了大部分我想要的样式。现在的样式就像每一个文章都是对前沿的技术探索了，有点好笑。不管怎么说也是很干净了，干净的界面才有想法继续写下去。


已经入职了快三个月，做的是 Agent 开发的工作，实际上工作量也没有那么饱和于是乎大部分还是自己学的时间。每天就是一顿哐哐的 Vibe Coding 已经了解各种模型，再去学一点 Harness 相关的东西。7-10 月，从 GPT-5.4 到现在的 6.1 Sol，每天的工作似乎变成一个狂热的模型追逐分子。Vibe 能创造各种各样的复杂功能，但是上起班来真没有以前古法编程的时候那样有趣，可以说是那种解密游戏一样的，创造逻辑的感觉。现在就是对话+等待的人机 Loop 。之后所需要做的可能就是去以架构思维去理解 Vibe 出来的东西吧。


尝试过 TRAE、Qoder、CodeX、Cursor等各种 Coding Agent，很多都是基于一些开源 Agen比如 PI 这些。因为了解了整个 Agent 原理所以感觉用起来确实比较有整体性了会考虑很多可能的情况，以及这个 harness 为什么感觉用起来缺失点什么。因为都是基于 ReACT 的工具链循环，所以可能会有工具调用方面的不同样的问题或者上下文的维护，整体提示词的对接啥的。关于上下文，以前我觉得 1M 是最好的，就是越长越好，但是我最近又看了下比如 Qwen 的研究报告，这些模型大部分原生的训练长度还是 200 多 K 也就是 20 多 W 上下文 Token 是用 Yarn 做扩展上下文得到最高 1M 的。之前上学的时候也研究过训练输入长度的，确实，现在的扩展上下文当推理的时候大于训练长度时，一般来说应该是比训练效果要开始递减的。所以现在也选择基本上原生 200K 左右的上下文，只要超过这个数基本上就是换个 Session 或者 Compact 了。


关于前端，AI 做出来的前端依旧是没有办法直视。要么有个交互稿去实现，不过实现起来仍旧是非完全还原的。要么就是多模态的模型给个参考图，不过依旧是不看参考图的时候更多点，像即便是 CodeX的模型也有 50% 的概率去自己写自己的样式。最好的方式我觉得是提炼出设计 token，也就是统一的设计规范加上设计稿应该是最好的。
