### WorkTree


从 Git 延伸过来的开发概念，比较适合 Vibe Coding。之前没有接触过 worktree 更多的是分支。因为 Vibe Coding 工作效率提高随之带来需要并行开发的需求，worktree 便是非常适合的选择。**本质是复制多个目录同时工作且互不覆盖写入打扰。**


**① 一个仓库，多个工作目录**


Vibe 时，主仓库不变，开俩个 Worktree，一个 Worktree A 去做登录界面，一个 Worktree B 去做设置界面。其中，互不打扰的原理是 Worktree 是基于真实磁盘创建的。


**② 每个目录可以处于不同分支**


创建 WorkTree 后，不同 Agent 可以在共享的 Git 树上的不同分支上修改各自负责的代码。


**③ 共享 Git 仓库数据，不共享工作区**


worktree 共享 Git 的对象数据库和仓库历史，但各自的工作文件、暂存区和工作区状态是独立的。


**Git 树是共享的!**


**④ 提交后，不会自动进入 main**


想让 `main` 获得这些改动，仍然需要 `merge`、`rebase` 或其他整合操作。


**⑤ 工作目录和分支可以分别清理**


`git worktree remove` 删除的是对应工作目录。它不会自动删除分支，也不会自动合并或删除已经提交的历史。


实践：举个例子我在 Qoder 里把桌面的 Test 目录作为工作区，在这个工作区使用了 Worktree。 然后 Qoder 就会在自己的软件缓存目录.qoder 里创建一个 worktree 随机命名的目录和分支，然后在里面做修改。但是实际上原桌面的 Test 工作区是没有任何改动的，最后依旧需要合并回去才能看到主目录的修改结果。
